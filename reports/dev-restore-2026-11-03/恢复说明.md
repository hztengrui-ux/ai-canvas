## 三个根因（互不相干）

1. **DSH 工程列表**：`C:\Users\Administrator\.dsh\storages\workspace.json` 是整文件原子替换，只在内存 mutation 时写盘。
   只要 DSH 进程还活着，外部改它必被内存副本覆盖（03:25 新建工作区时又冲了一次）。
   修法：等 DSH 完全退出后再合并写（`dsh-restore-workspaces.mjs --watch` 就是干这个的）。
2. **dev 模式没有后端**：`electron/main.cjs:229` 的 `if (IS_DEV) return DEV_URL;` 让开发模式直接加载 Vite 页面，不启动 `server/index.js`，
   所以登录必报「无法建立本地会话」。修法：dev-start 额外以 5181 端口起后端。
3. **Electron 在本机的两个硬约束**（实测二分得出，与 ACL 无关）：
   - `--user-data-dir` 必须在 `E:\DSH项目` 之内，否则 `process_singleton_win.cc(465) Lock file can not be created! Error code: 5`；
   - 必须 `--no-sandbox`，否则 `0x80000003 STATUS_BREAKPOINT`。

## 旧项目数据怎么来的

- `src/project.js` 把项目存在 localStorage：`ai-canvas.project.graph.v1`（当前画布，单槽）、`ai-canvas.projects.v1`（列表）等，服务端不存项目。
- localStorage 按 origin 隔离：旧应用是 `http://127.0.0.1:5181`，dev 是 `http://127.0.0.1:5180`。
- 从 `E:\ai-canvas-data\chrome-profile\Default\Local Storage\leveldb`（最后写 10/18）用 headless Chrome 导出 6 个键，再通过 CDP 注入 dev origin。
- 效果：项目页出现「未命名项目 10/18 09:46」；注入 `graph.v1` 后进画布是旧图（参考图 / 画面描述 / 执行 / 结果，4 节点 3 连线，视口 123%）。
- 注意单槽模型：`openProject()` 只切项目名和 id，画布内容看 `graph.v1` 里存的是哪份；注入要在首页做再刷新，否则画布卸载的 `flushSave` 会覆盖掉。
