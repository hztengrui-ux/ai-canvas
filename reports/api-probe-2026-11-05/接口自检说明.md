## 一、这次做了什么

### 1) 后端：新增自检能力 `server/providers/probe.js`

- 覆盖 5 个目标：`openai` / `gemini` / `jiemeng`（火山方舟）/ `llm`（豆包语义）/ `comfyui`
- 探测方式（都是免费、极轻量的调用）：
  - 列表型：`GET {baseUrl}/models`（OpenAI 风格 `Authorization: Bearer`；Gemini 用 `x-goog-api-key` 头）
  - 对话型：`POST /chat/completions`，`max_tokens: 1`
  - ComfyUI：`GET /system_stats`
- 把失败翻译成可执行的 `code`（前端直接展示中文提示 + 该改哪个输入框）：

| code | 含义 | 典型原因 |
|---|---|---|
| `OK` | 通 | — |
| `NO_KEY` | 没填 Key | 输入框空着 |
| `AUTH` | Key 无效 | 复制不全、过期、用了别的站的 Key |
| `FORBIDDEN` | Key 没权限 | 项目/模型未开通 |
| `PATH` | 地址错 | baseUrl 少了 `/v1`、多了斜杠、用了控制台地址 |
| `MODEL` | 模型名错 | 上游改了名；需在「模型 ID 覆盖」里填真实名 |
| `RATE` | 限流 | 上游 429 |
| `TIMEOUT` | 超时 | 网络/代理没生效 |
| `NETWORK` | 连不上 | DNS/防火墙/服务没起（ComfyUI） |
| `UPSTREAM` | 上游 5xx | 厂商故障 |

- 端点：`POST /api/providers/probe`，body `{provider, baseUrl?, model?, apiKey?}`。
  - 覆盖值**只用于这次探测、不落盘**；`apiKey` 语义：不传=用已保存的 Key；`null`/`""`=明确"这次没有 Key"（应报 NO_KEY，而不是偷偷用旧 Key 假装成功）。
  - 回包里**不回显 Key**（页面 JS 与 DevTools 都能读到回包，回显就是泄露）。
  - 单独限流 120 次/分钟（一次"一键自检"会连打 5 个目标，通用 30 次/分钟会挡住正常用户）。

### 2) 前端：`src/components/SettingsDialog.vue`

- 设置抽屉顶部「一键自检全部接口」+说明文案（免费探测、不生成图片、不扣算力、用当前表单里还没保存的值）
- 每个 provider 的 Key/模型后面加「测试连接」按钮，结果就地显示：红色/绿色一句话 + 可执行提示（如"确认地址以 /v1 结尾"）
- 掩码 Key 不参与探测（拿 `sk-****` 去测必然 401）；用户清空输入框时按 `null` 提交，明确报"还没填写 API Key"

### 3) 测试：`server/__probe.test.mjs`（24 项）

本地假上游（http 服务器）模拟 `/v1/models`、`/v1/chat/completions`、Gemini `models`，断言：
- NO_KEY / UNSUPPORTED、Key 错→AUTH、地址错→PATH、模型名错→MODEL、连不上→NETWORK、429→RATE
- Gemini 用 `x-goog-api-key` 头；LLM 发的是 `max_tokens=1`；**全程没有发起图片生成请求**（不扣算力）
- 回包不回显 Key
- 纯函数：拒绝 `ftp://`、拒绝把账号密码写进地址、去尾斜杠

已接入 `scripts/run-tests.mjs` → 现在全量 **35 套测试全绿**（原 34 + 新增"模型 API 自检"）。

## 三、云端化方案（交付文档，未动代码）

`reports/cloud-migration-2026-11-05/云端化方案.md`，要点：

- **现状**：账号/会话/账本/订单/审计都是 JSON 文件；项目数据只在浏览器 localStorage（服务端没有项目库）；厂商 Key 在用户机器的保险箱里。
- **结论**：上云 = 把 7 类本地存储换成服务端存储 + 中间加一层 `server/storage` 适配层（file / pg 两套实现），而不是换服务器地址。
- **技术栈**：沿用 Express；PostgreSQL 16 + Redis 7 + S3 兼容对象存储 + Caddy。
- **分阶段**：P0 地基 3 天（Docker 化 + storage 适配层 + 迁移目录）→ P1 账号上云 4 天 → P2 项目/文件上云 8 天 → P3 上线 5 天；合计约 3 周。
- **关键设计**：项目保存用 `baseRevision` 乐观锁，冲突返回 409 + 服务端快照；老账号 scrypt 校验通过后自动重哈希为 argon2id；云端模式下厂商 Key 只留服务端。
- **可部署骨架（阶段 0，已落盘）**：`deploy/Dockerfile`、`deploy/docker-compose.yml`、`deploy/Caddyfile`、`deploy/.env.example`、`deploy/README.md`
  - ⚠️ 已验证的坑已写进 README：容器 `hostname` 必须固定（vault 密钥由 `os.hostname()` 派生，变化则 Key 全解不开）；`AI_CANVAS_BIND=0.0.0.0`；`/api/session` 只对回环发令牌，所以阶段 0 只适合"服务端可用性验证"，真正给浏览器用必须等 P1 账号体系。
