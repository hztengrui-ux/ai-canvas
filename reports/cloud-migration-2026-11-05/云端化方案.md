# 跨多多 AI 创作台 · 云端化方案（账号 / 数据全部上云）

> 版本：v1 · 2026-11-05
> 范围：把「本地单机版」升级为「云端 SaaS」：账号、会话、项目、素材、产出、算力账本、订单、审计全部在云；
> 桌面端/浏览器端只做展示与本地缓存。本文只写**怎么做**，不含报价承诺与具体厂商绑定。

---

## 0. 一句话结论

现在的后端是**可用的单机后端**，但存储层是"每个模块自己读写 JSON 文件"。
上云不是换一个地址，而是**把 7 类本地存储换成服务端存储**（账号/会话、项目、素材、产出、账本、订单、审计），
并在中间加一层**存储适配层**，让「本地模式」和「云端模式」跑同一套业务代码——这是整个迁移的地基（P0）。

预计工期：**1 人约 3 周**（P0 3 天 / P1 4 天 / P2 8 天 / P3 5 天），可按阶段上线，不必等全部做完。

## 1. 现状盘点（代码实测）

| 模块 | 现状存储 | 具体位置 | 云端目标 |
|---|---|---|---|
| 账号 | JSON | `server/accounts.js` → `users.json`（scrypt 加盐） | `users` 表（argon2id） |
| 会话 | JSON + 内存 Map | `sessions.json` → `sessions` | `sessions` 表（refresh token 旋转） |
| 角色/部门 | JSON | `rbac.js` → `roles.json` / `depts.json` | `roles` / `departments` / `role_permissions` |
| 算力账本 | JSON | `credits.js` → `credits-ledger.json` | `credits_ledger`（append-only）+ `wallet` 快照 |
| 订单/充值 | JSON | `payments.js` → `recharge-orders.json` | `orders`（幂等键 + 回调日志） |
| 批量任务 | JSON | `batch.js` / `filebatch.js` | `jobs` 表 + Redis 队列 |
| 血缘 | JSON | `lineage.js` | `asset_lineage` |
| 素材 | 本机目录 | `config.js` → `materialDir` | 对象存储（S3/OSS）+ `assets` 表 |
| 产出图 | 本机目录 | `outputsDir` | 对象存储 + `assets` 表（含签名 URL） |
| 配置/密钥 | `config.json` + 保险箱 | `vault.js`（系统钥匙串或文件） | 服务端加密列 + KMS；**客户端不再持有厂商 Key** |
| 审计 | JSONL 按天 | `audit.js` → `audit/*.jsonl` | `audit_logs`（按月分区） |
| **项目数据** | **renderer localStorage** | `src/project.js`：`ai-canvas.project.graph.v1` / `projects.v1` / `assets.v1` / `meta.v1` | `projects` / `project_versions` 表 + 增量同步 API（**最大改动**） |
| 模板 | 文件 | `templates.js` | `templates` 表（版本化） |

两个关键事实，决定了工作量：

1. **项目数据目前不在服务端**，只在浏览器/Electron 的 localStorage（按 origin 隔离）。上云就等于"新增一个项目服务"，要设计版本、冲突与迁移。
2. **厂商 API Key 现在存在用户机器上**（vault），由本地后端代发请求。上云后 Key 只能存在服务端，客户端调自己的云 API，由云端计费——这同时是收益（Key 不外泄、可审计）和风险（云上 Key 泄露=直接资损）。

## 2. 目标架构

```
┌──────────────────────┐        HTTPS         ┌────────────────────────────┐
│ 桌面端 (Electron)     │ ───────────────────▶ │  Caddy（自动 TLS / 反代）    │
│ 浏览器端（可选）       │                      └────────────┬───────────────┘
└─────────┬────────────┘                                   │
          │ 本地缓存：项目快照、离线队列、图片缩略图              ▼
          │                                     ┌────────────────────────────┐
          │                                     │  API 服务（Node 20 + Express）│
          │                                     │  鉴权 / 计费 / 生成代理 / 同步 │
          │                                     └───┬────────┬────────┬───────┘
          │                                         │        │        │
          │                              ┌──────────▼──┐ ┌───▼─────┐ ┌▼──────────────┐
          │                              │ PostgreSQL  │ │ Redis   │ │ 对象存储 S3/OSS │
          │                              │ 业务数据     │ │会话/队列 │ │ 素材 / 产出图    │
          │                              └─────────────┘ └─────────┘ └───────────────┘
          │
          └── 厂商模型 API（OpenAI / Gemini / 方舟 / 万相）只由云服务端调用
```

技术选型（沿用现有代码、最小重构）：

| 层 | 选择 | 理由 |
|---|---|---|
| API | 现有 Express 代码 + Docker | 61 个路由已验证，重写无收益 |
| 数据库 | PostgreSQL 16 | JSONB 可承接现有配置结构；事务、行锁、迁移工具齐全 |
| 缓存/队列 | Redis 7 | 限流、会话黑名单、批量任务队列、分布式锁 |
| 对象存储 | S3 兼容（阿里 OSS / 腾讯 COS / 自建 MinIO） | 预签名 URL 直传，API 不中转大文件 |
| 反向代理 | Caddy | 自动 HTTPS、配置最短 |
| 迁移 | `dbmate` / `node-pg-migrate` | SQL 迁移可审阅 |
| 前端 API 基址 | 运行时注入 `window.__AI_CANVAS_API__` + 构建期 `VITE_API_BASE` | 一套前端同时支持本地/云 |

## 3. 数据模型（DDL 草案）

只列核心表；`bigserial` 主键、`timestamptz` 时间、软删除用 `deleted_at`。

```sql
-- 账号（保留本地 scrypt 迁移能力：password_algo 记 'scrypt' 或 'argon2id'）
create table users (
  id            bigserial primary key,
  username      text not null unique,
  nickname      text not null default '',
  email         text unique,
  phone         text unique,
  password_hash text not null,
  password_algo text not null default 'argon2id',
  role_id       bigint not null default 1,
  dept_id       bigint,
  status        text not null default 'active',      -- active / locked / disabled
  created_at    timestamptz not null default now(),
  updated_at    timestamptz not null default now()
);

-- 会话：一个设备一行，refresh 旋转 + 可撤销
create table sessions (
  id             bigserial primary key,
  user_id        bigint not null references users(id) on delete cascade,
  token_hash     text not null unique,               -- sha256(refresh_token)，明文不落库
  device_name    text not null default '',
  device_id      text not null default '',
  ip             text not null default '',
  ua             text not null default '',
  remember       boolean not null default false,
  created_at     timestamptz not null default now(),
  last_seen_at   timestamptz not null default now(),
  expires_at     timestamptz not null,
  revoked_at     timestamptz
);
create index sessions_user_idx on sessions(user_id) where revoked_at is null;

-- 项目：元数据（画布都在 version 里）
create table projects (
  id           text primary key,                     -- 沿用现有 proj-xxxx id，迁移不改 id
  user_id      bigint not null references users(id) on delete cascade,
  name         text not null default '未命名项目',
  thumb_key    text,                                 -- 对象存储 key
  revision     bigint not null default 1,            -- 乐观锁，客户端写时必须带
  created_at   timestamptz not null default now(),
  updated_at   timestamptz not null default now(),
  deleted_at   timestamptz
);
create index projects_user_updated_idx on projects(user_id, updated_at desc);

-- 画布快照：保留最近 N 版，便于回滚与冲突排查
create table project_versions (
  id          bigserial primary key,
  project_id  text not null references projects(id) on delete cascade,
  revision    bigint not null,
  graph       jsonb not null,                        -- 现有 KEY_GRAPH 的 graph 原样
  meta        jsonb not null default '{}',           -- 视口 / 画布模式 / 名称
  created_by  bigint references users(id),
  created_at  timestamptz not null default now(),
  unique (project_id, revision)
);

-- 素材/产出：文件在对象存储，库里只存元数据；embedding 可选（pgvector）
create table assets (
  id          bigserial primary key,
  user_id     bigint not null references users(id) on delete cascade,
  project_id  text references projects(id) on delete set null,
  kind        text not null,                          -- material / output / thumb
  bucket_key  text not null,
  bytes       bigint not null default 0,
  mime        text not null default '',
  width       int, height int,
  tags        jsonb not null default '{}',            -- 品类/渠道/风格/季节…（VLM 打标）
  source      text not null default 'upload',         -- upload / generate / import
  sha256      text,
  created_at  timestamptz not null default now(),
  deleted_at  timestamptz
);
create index assets_user_created_idx on assets(user_id, created_at desc);
-- 需要以图搜图时再开：create extension vector; alter table assets add column embedding vector(768);

-- 算力账本：只追加，余额由 ledger 推导 + wallet 快照兜底
create table credits_ledger (
  id          bigserial primary key,
  user_id     bigint not null references users(id),
  delta       integer not null,                       -- 正=充值/退款，负=消耗
  reason      text not null default '',
  ref_id      text,                                   -- 幂等键：任务 id / 订单 id
  balance_after integer,
  created_at  timestamptz not null default now(),
  unique (user_id, ref_id, reason)
);
create index ledger_user_idx on credits_ledger(user_id, created_at desc);

-- 订单
create table orders (
  id          text primary key,
  user_id     bigint not null references users(id),
  amount_cents int not null,
  credits     int not null,
  channel     text not null,                          -- wechat / alipay / manual
  status      text not null default 'pending',        -- pending / paid / cancelled / refunded
  out_trade_no text,
  paid_at     timestamptz,
  created_at  timestamptz not null default now()
);

-- 任务（批量/单次生成）
create table jobs (
  id         text primary key,
  user_id    bigint not null references users(id),
  kind       text not null,                           -- generate / batch / filebatch
  status     text not null default 'queued',          -- queued / running / done / failed / cancelled
  payload    jsonb not null default '{}',
  result     jsonb,
  error      text,
  started_at timestamptz,
  finished_at timestamptz,
  created_at timestamptz not null default now()
);

-- 审计
create table audit_logs (
  id         bigserial primary key,
  user_id    bigint,
  action     text not null,
  detail     jsonb not null default '{}',
  ip         text default '',
  ua         text default '',
  created_at timestamptz not null default now()
) partition by range (created_at);   -- 按月分区，保留 12 个月
```

## 4. 存储适配层（P0 的核心）

目标：**同一份业务代码，跑本地文件或云数据库**。做法是把"各模块直接 fs 读写"收敛成仓储接口。

```
server/storage/
  index.js          # 按 AI_CANVAS_STORAGE 选择实现
  types.js          # 接口注释（JSDoc typedef），无运行时代码
  file/             # 现有 JSON 逻辑挪进来，行为保持不变
    users.js sessions.js projects.js assets.js credits.js jobs.js audit.js
  pg/               # 新增：Postgres 实现
    users.js sessions.js projects.js assets.js credits.js jobs.js audit.js
  blob/
    fs.js           # 本地目录（现状）
    s3.js           # 预签名上传 + 下载 URL
```

接口示例（每个仓储 4~6 个方法，够用就好）：

```js
// storage/types.js 里的约定（示意）
usersRepo = {
  findByUsername(username),
  findById(id),
  create({ username, passwordHash, algo, roleId, ... }),
  updatePassword(id, hash, algo),
  list({ page, size })
};

projectsRepo = {
  list(userId, { cursor }),
  get(userId, projectId),
  create(userId, { id, name, graph, meta }),
  saveVersion(userId, projectId, { baseRevision, graph, meta }), // 冲突返回 CONFLICT + 服务端最新
  remove(userId, projectId)
};
```

**双写灰度**：`AI_CANVAS_STORAGE=pg` + `AI_CANVAS_MIRROR=file` 时，写 PG 成功后再写一份文件（只记日志不阻塞），
观察 1~2 周后关掉镜像；回滚只需把环境变量改回 `file`。

## 5. 认证与安全

| 项 | 方案 |
|---|---|
| 密码 | `argon2id`（m=19MiB,t=2,p=1）；老账号首次登录用 scrypt 校验通过后**自动重哈希** |
| 访问令牌 | JWT HS256，15 分钟，payload: `sub / role / sid` |
| 刷新令牌 | 随机 32B，只存 `sha256`；30 天；每次刷新**轮换**并把旧 token 标 revoked（重放检测） |
| 多设备 | `sessions` 一设备一行；设置页可"退出其他设备" |
| 厂商 Key | 只存服务端（`provider_keys` 加密列，主密钥来自 KMS/环境变量，绝不入库明文）；客户端只拿到 `hasKey: true` |
| 生成代理 | 客户端调 `/api/generate`，云端校验额度→预留→调用厂商→结算；Key 永不出服务端 |
| 限流 | Redis 令牌桶：用户维度（每分钟/每天）、IP 维度、全局预算熔断 |
| 审计 | 所有写操作 + 登录/登出/改密/Key 变更/退款，记 `who/what/ip/ua` |
| 传输 | 全站 HTTPS；HSTS；Cookie 不用（Bearer） |
| 文件 | 预签名 URL 直传，API 不转发二进制；上传前校验类型与大小，下载走短时效签名 |

**必须做的一件事**：云端模式下禁用现在的「本机会话令牌」旁路（`/api/session` 现在只发给本机，这是本地版的安全基础；
上云后所有入口都走账号鉴权，避免"知道地址就能拿令牌"）。

## 6. 项目数据上云（P2，最大一块）

现状：`src/project.js` 单槽模型，`localStorage` 只放"当前项目"，`projects.v1` 只是列表。

目标 API：

```
GET    /api/projects?cursor=            → 列表（id,name,thumb,revision,updatedAt）
GET    /api/projects/:id                → { project, version }
POST   /api/projects                    → 新建（客户端可带本地 id，便于离线创建）
PUT    /api/projects/:id                → body { baseRevision, graph, meta }
                                          200 → 新 revision
                                          409 → { code:"CONFLICT", server:{revision,graph,meta} }
DELETE /api/projects/:id                → 软删除
```

冲突策略（先简单后精细）：

1. **乐观锁**：客户端每次保存带 `baseRevision`；服务端比对，不一致返回 409 + 服务端最新快照。
2. 客户端策略：单人项目 → 提示"云端有更新，用云端覆盖本地 / 用本地覆盖云端 / 另存为副本"；
   多人协作 → 后期再做 OT/CRDT（Vue Flow 的图结构做 CRDT 成本高，先不做）。
3. **本地缓存**：桌面端保存一份最近项目快照（`userData/projects-cache.json`），断网可继续编辑，恢复后进同步队列。
4. **迁移**：上线时读客户端 localStorage，一次性 `POST /api/projects` 全量导入，校验条数与节点数后清标记。

## 7. 分阶段实施

### P0 · 地基（约 3 天）
- 现有服务 Docker 化（`deploy/`，见附录 A），单实例可跑（数据仍在卷上）——先让"部署"这条路通
- 引入 `server/storage/` 适配层：把 accounts/sessions 读写挪到 `file` 实现（行为不变，测试全绿）
- 引入 `dbmate` 迁移目录 `db/migrations/`，写 0001 初始 schema
- CI：`npm test` + 迁移 dry-run

**验收**：本地模式行为 100% 不变，35 套测试全绿；`docker compose up` 能在服务器上起服务并访问。

### P1 · 账号上云（约 4 天）
- `users` / `sessions` / `roles` 切 PG；scrypt→argon2id 在线重哈希
- 注册/登录/刷新/登出/改密/设备管理接口
- 登录限流、失败锁定（沿用现有 5 次/5 分钟策略）
- 老账号迁移脚本：`E:\ai-canvas-data\users.json` → PG，保留 id 映射

**验收**：两台设备同时登录、刷新轮换、撤销设备、老密码可登录且自动升级哈希。

### P2 · 项目与文件上云（约 8 天）
- `projects` / `project_versions` / `assets` 表 + API
- 对象存储接入（预签名直传；产出图由云端上传）
- 前端改造：`src/project.js` 从 localStorage 改为 API + 本地缓存；冲突 UI
- 素材库/产出图 URL 从 `/outputs/...` 改为签名 URL（保留本地模式兼容）
- 迁移：本地 JSON/localStorage → 云

**验收**：A 机器建项目，B 机器登录可见可编辑；断网编辑后恢复自动同步；两处同时改有冲突提示。

### P3 · 上线（约 5 天）
- 域名 + HTTPS + 备份（pg_dump 每日、OSS 版本化）+ 监控（健康检查、错误率、队列积压）
- 灰度：内部账号先切云，桌面端设置里保留"本地/云"开关
- 回滚演练：切回 `AI_CANVAS_STORAGE=file` + 本地数据不丢
- 合规：隐私政策、账号注销、数据导出

## 8. 部署与运维（阶段 0 就能用）

见附录 A 的 `deploy/` 三件套（Dockerfile / docker-compose.yml / README）。

要点：
- 数据卷 `/data`（AI_CANVAS_HOME）必须落在云盘并**每日快照**
- 反代用 Caddy 自动签发证书；只暴露 443
- Postgres 不要暴露公网端口；备份到对象存储
- 健康检查：`GET /api/session`（200 即活）；再加 `/healthz` 更明确（P1 顺手加）
- 日志：stdout + 文件轮转；P1 接结构化日志（JSON）

成本粗算（国内云，1 台 4C8G + 200G SSD + 100G 对象存储 + 5M 带宽）：约 ¥300~600/月；托管 PG 另加 ¥150~400/月。
真实成本取决于出图量和存储增长，建议先按"1 台 + 自建 PG"起步。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 项目 localStorage→云 迁移丢数据 | 用户作品丢失 | 迁移前强制导出 JSON 备份；迁移后校验条数/节点数；保留 30 天回滚快照 |
| 并发保存冲突 | 覆盖别人改动 | 乐观锁 + 409 提示；服务端保留版本历史 |
| 云端厂商 Key 泄露 | 直接资损 | 加密列 + KMS + 不出服务端 + 额度熔断 + 异常用量告警 |
| 大文件流量费用 | 成本失控 | 预签名直传、缩略图、按需清理、对象存储生命周期 |
| 单机故障 | 全站不可用 | 至少每日备份 + 可 1 小时内从备份重建；后续再加只读副本 |
| 域名未备案（国内服务器） | 80/443 被拦 | 提前备案，或用境外节点（注意跨境延迟与合规） |
| 支付回调外网可达 | 伪造回调 | 沿用现有验签；回调 IP 白名单 + 幂等键 |

## 10. 下一步（建议顺序）

1. **P0 第一天**：把 `server/storage/` 接口与 `file` 实现搭起来，测试不动（风险最低，收益最大）
2. 同时准备 P1 的 `0001_init.sql`
3. 云端环境到位后（服务器/域名/备案），直接进 P1，2 天内就能"账号先上云"
