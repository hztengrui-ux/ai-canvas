## 二、它是什么：架构与数据流

### 2.1 定位

**桌面版 AI 电商视觉创作工具，按用量付费。** 核心交互不是对话框，而是**无限节点画布**：
拖入商品图/参考图/提示词 → 连线组成工作流 → 一键出主图/模特图/详情页/短视频。工作流可保存、复刻、批量跑。

### 2.2 技术栈（实测版本）

| 层 | 选型 | 实际安装版本 | 文档声明 |
|---|---|---|---|
| 前端 | Vue 3 `<script setup>` | 3.5.42 | ^3.5.0 |
| UI 组件 | Element Plus + icons | ✅ | ^2.9.0 |
| 画布 | Vue Flow（core/background/controls/minimap） | 1.48.2 | ^1.48.2 |

| 凭据存储 | @napi-rs/keyring + 本地加密文件 | 2.0.0 | ^2.0.0 |

### 2.3 三层结构

```
┌─ 渲染层（Vue 3 + Element Plus + Vue Flow）
│    src/  65 文件 = .vue 41 + .js 13 + .mjs 3 + .css 8（逻辑代码 .vue/.js/.mjs 共 57 个 / 0.42 MB）
│    NodeCanvas.vue 单文件即占逻辑代码 ~15.6%
│
├─ 本地后端（Express，只绑 127.0.0.1）    ← 为什么桌面端要内嵌后端：见下
│    server/  25 个 .js（server 根 18 + providers 7）；另有 14 个 __*.test.mjs（server 11 + src 3）
│    路由：index.js 49 条 + admin.js 17 条 = 66 条（另有 8 处 app.use 挂载）
│
└─ 桌面壳（Electron）
     electron/main.cjs（主进程/单实例/动态端口）+ preload.cjs（安全桥）+ updater.cjs
```

**为什么内嵌本地后端**：AI 供应商的 Key 不能进渲染进程（XSS 即泄露）；且需要本地文件系统能力
（`outputs/` 落地、素材库、ComfyUI 本地调用）。后端只监听 `127.0.0.1`，不对外暴露。

### 2.4 一条生成请求的完整链路

```
画布执行节点
  → POST /api/generate（SSE 长连接）
     ├─ security.js 五道门：Host 校验 → Origin 校验 → 令牌 → 令牌桶限流 → 并发槽
     ├─ upstream.js 算签名 usig_v2_<hash>（内容级幂等键）
     │    └─ 命中缓存？→ 直接 done，cost=0，savedCost=N（不扣费）
     ├─ credits.js 预扣（余额不足则拒绝）
     ├─ providers/*（万相 / 即梦 / OpenAI / Gemini / ComfyUI）
     ├─ lineage.js 落血缘 sidecar（prompt/model/种子/参考图/花费 → 可复现）
     └─ SSE 事件：queued → progress → done
          ├─ 成功 → credits 提交（流水落账）
          └─ 失败/取消 → credits 回滚（原额退回）
```

### 4.1 🔴 严重

- **`src/ports.js` 不是网络端口**，是**画布连线端口类型系统**（`DATA_TYPES`/`NODE_PORTS`/`validateConnection`）。

  要做多画布或把画布抽包，第一步应是收成一套。

## 九、独立复验结果

> 三条最严重的后端结论由独立复验员用**真实 HTTP 行为**复现（隔离目录 + `vault=file`，不读源码下结论）。
> 报告：[reports/verify-backend-adversarial.md](reports/verify-backend-adversarial.md)；
> 复现脚本与实测日志：`reports/verify/{v1-slot-leak,v2-privesc,v3-ledger,v4-cache}.mjs` + `out-v1..v4.txt`。

| 编号 | 结论 | 判定 | 关键实测 |
|---|---|---|---|
| V1 | 并发槽在"算力不足"早退路径泄漏 | ✅ **成立（真）** | 余额 0 账号连发 2 次 → `inFlight` 1→2；**第 3 次被拒文案从"算力不足"变成"同时进行的生成任务过多"**；等 2.5s 不自愈；连余额 500 的超管也一起被拒。视频路由同病 |
| V2 | 运营角色可自我提权 / 重置超管 | ✅ **成立，且比原报告更严重** | `/reset` 后新密码登录超管 200（接管成功）；运营 PUT 自己 `roleIds:["r-super"]` → 200，权限 **8→15**。**新增第 3 条更短路径**：运营 `POST /api/admin/accounts` 直接带 `roleIds:["r-super"]` 造超管（`accounts.js:160` 无白名单） |
| V3a | 失败重跑永不退款 | ✅ **成立（真）** | 实测流水：+100 → reserve(−10) → rollback(+10) → reserve(−10) → reserve(−10)；第 2 次 rollback 返回 `{ok:true,skipped:true}`（`refunded=undefined`），**余额永久停在 90**，无自动补偿。不同 refId 对照正常退回 |
| V3b | 流水裁剪破坏余额不变式 | ✅ **成立（措辞需修正）** | 2100 笔 ×1 点后 `balance()=2000`（**100 点蒸发**），`reconcile` 报 `{sum:2000, recorded:2001}`。修正：`balance()` 恒等于"剩余流水求和"（同义反复不会破），坏的是**"余额 = 全部流水求和"与 reconcile 记录值** |
| V4 | 上游缓存"单槽覆盖、跨用户泄漏" | ❌ **误报（定级错误）** | `cacheGet` 严格 `entry.userId !== userId → null`，实测 B 查 A 的签名恒为 `null`（fail-closed），不同签名可共存。"单槽覆盖"不成立。真实副作用仅"同签名跨用户互相挤掉缓存条目"（可用性，非安全） |

（`index.js:576/686/907/969`），无中间件、无定时器兜底，`inFlight` 无 TTL。

**结论修正（依据交叉核查）**：原后端报告的"23 条风险（严重 4 / 高 5 / 中 9 / 低 5）"中，

### 12.2 修了什么（逐条）

**R1 · 并发槽泄漏 → 未授权全局 DoS**（`server/index.js`）
- 把 `/api/generate` 与 `/api/generate-video` 里「签名 → 命中缓存 → 预扣」整段纳入 `try`，
  `finally` 统一 `releaseSlot()`；只有 `acquireSlot()` 自身失败才提前返回。
- 顺带修掉一个同源隐患：`await credits.reserve()` 若抛异常，旧代码也会漏槽（现已被外层 `finally` 兜住）。
- **验收**：余额 0 账号连发 2 次 → 两次都正确报「算力不足」，`inFlight` 回到 0，
  **第 3 次不再被「同时进行的生成任务过多」拒绝**；视频路由同测。

**R2 · 运营角色越权提权 / 接管系统**（`server/accounts.js` + `server/admin.js`）
- 新增 `assertCanGrantSuper()`：**只有超管能授予 `r-super`**，同时收口 `createUser`（原报告遗漏的第 3 条最短路径）。
- `adminResetPassword()`：**换超管密码必须操作者本身是超管**。
- `updateUser` / `deleteUser` / 停用 / 强制下线：非超管不得操作超管账号。
- 首次初始化（`users` 为空）保留直建超管的能力，不破坏首次进入流程。
- **验收**：三条利用路径全部 400 被拒；超管原密码仍可登录（确实没被改）；
  **运营改自己昵称仍返回 200**（未矫枉过正误伤正常功能）。

**R3 · 充值链路 404 / 伪支付**（`server/index.js` + `src/api.js` + `AccountModals.vue`）
- 前端调的 `/api/recharge/orders/:id/paid` **服务端从未实现** → 点支付必 404。
- 新增 **`POST /api/recharge/orders/:id/simulate-paid`**：由服务端用沙箱私钥签发回调票据，
  走与真实网关**完全相同**的 `handleCallback`（验签 → 金额校验 → 幂等 → 到账）。
- 安全边界：仅在 `sandbox` 模式开放；一旦配置真实商户号/AppId 直接 **403**。
- 旧 `/paid` **仍然是 404**（无后门），`__payments.test.mjs:155` 的断言继续成立。
- **验收**：创建 1000 点订单 → 余额 500 → **1500**；重复调用返回「订单已支付」且余额不再变（幂等）。

**R4 · 账务两处资损**（`server/credits.js`）
- `reserve()` **加幂等**：同一 `refId` 已有未了结预扣时直接复用，不再重复扣费；
  `rollback()` 优先按 `reserveTxId` 精确匹配。
  → 修掉「同一任务失败两次，第二次预扣被重复扣、而回滚被去重挡掉 → 用户永久少一笔钱」。
- `append()` **裁旧不再吞余额**：超 2000 条时把被丢弃金额之和写成一条 `carry` 结转记录置于队首，
  保证「余额 == 流水求和」不变式恒成立（数组上限放宽到 2001，是有意取舍）。
- **验收**：充 2100 笔 ×1 点后 **余额仍是 2100**（旧实现蒸发 100），`reconcile` 一致；
  同 `refId` 重复预扣只扣一次、只退一次。

**R5 · 测试基线恒红**（`src/__theme.test.mjs`）
- `:52` 断言写死 `DEFAULT_THEME === "aurora"`，而 `src/theme.js:54` 已是 `"atelier"`
  → `npm test` 长期恒失败，谁都分不清「环境坏了」和「真回归」。
- 改为锁定 `"atelier"` **并**补两条结构性断言（默认主题必须存在于注册表、定义完整），
  以后改名会给出可读的失败信息而不是静默失效。

**结论：这不是打包一下就有的事。** 实测障碍：

| 障碍 | 实测 |
|---|---|

| 依赖 Electron 桥 | `window.desktop` **12 处** |
| 数据全在本机 | 账号/账本/项目都在本地文件，安卓沙箱下要换存储 |

| 路线 | 做法 | 预估 |
|---|---|---|
| **A. WebView 套壳 + 云端后端** | 现有前端打进 WebView，后端部署到服务器 | **3–5 天**（不含云部署/备案） |

**建议先走 A**（投入最小、最快验证价值）；目标是"卖安卓 App"则按 B 立项。

### 16.2 做了哪五件事

**O1 · 代码分割**（`vite.config.js`）
- 原来**零代码分割**：单个 1615KB 的 `index-*.js`。改任意一行代码，用户都要重下全部 1.6MB。
- 现在按依赖边界 `manualChunks` 切成 5 个包，vendor 命中浏览器缓存，业务包只 247KB。
- 分包只作用于 `node_modules`，业务代码留在主包（便于按需更新）。
- 注意：Electron 是本地加载，分包不会带来额外网络往返；Web/远程访问收益更明显。

**O2 · 移出 12.11MB 生成源图**（`public/templates/` → 根目录 `_template-src/`）
- `public/` 下的 7 张 `A_clean_modern_marketing_illus_*.png`（12.11MB）是生成 11 张 webp 时的**中间产物**，
  vite 每次都把它们拷进 `dist`、再由 strip 插件删掉 —— **白拷一遍**。
- 已移到 `_template-src/` 备份（保留可重新生成 webp），并加进 `.gitignore`。
- **顺带更正一处过期注释**：`vite.config.js` 原注释说这些 PNG"带只读属性，移不走也删不掉"——
  实测**并不成立**（都是普通 Archive 属性）。已改正，并把 strip 插件改为**防御性保留**
  （万一有人把图又拷回 `public/`，构建仍不会打进 dist）。

**O3 · 删除危险文件 `__probe.mjs`**
- 它硬编码 `os.homedir()`，**绕过一切数据隔离，直接覆写真实账本**
  `~/.ai-canvas/credits-ledger.json`。你账本目录里那个 `credits-ledger.json__probe`
  就是它留下的痕迹。
- 已删除；备份为 `scripts/_removed-probe.mjs.bak`（不再是 `.mjs`，不会被误执行），
  测试里保留一条断言确保它不会再回来。

**O4 · 删除死代码**
- `src/components/_deprecated/`（`InfiniteCanvas.vue` + `PromptPanel.vue`，407 行）：
  全仓库零引用，且它们 import 的 store 导出**早已不存在** → 一旦被误引用会直接抛错。
- `test_gen.py`（临时脚本）。备份在 `scripts/_removed-deprecated/`。

**O5 · 修正静态资源缓存策略**（`server/index.js`）
- 发现真问题：`express.static` 默认给 `Cache-Control: public, max-age=0`，
  于是**每个带 hash 的资源每次启动都要回源做一次 304 校验** —— 首屏 8 个资源就发 8 次校验。
- 改为按可缓存性分开（实测已确认生效）：

| 路径 | 策略 | 为什么 |
|---|---|---|
| `/assets/*`（文件名自带内容 hash） | `max-age=31536000, immutable` | 内容变了文件名就变，可永久缓存 |
| `/index.html` | `no-cache` | 它是"指针"，必须每次拿最新 bundle 引用，否则用户永远加载旧版 |
| `/brand` `/cases` `/templates`（无 hash） | `max-age=604800, stale-while-revalidate=86400` | 中间档 |

### 16.3 新增回归测试（防止被改回去）

`src/__perf.test.mjs`（**22 项**，已接入 `npm test` 成为第 17 套）：
- O1 必须配 `manualChunks`，且产物里真的存在多个 js 包、业务包必须小于 element 包且 < 400KB
- O2 `public/templates` 不得再出现生成源 PNG，但 11 张 webp 必须还在，`_template-src/` 必须存在
- O3 `__probe.mjs` 必须不存在，且备份文件里确实能看到"覆写真实账本"的代码（删除理由可追溯）
- O4 `_deprecated/` 必须不存在，且**代码文件**里不得再有引用（文档里提到是正常的，已排除）
